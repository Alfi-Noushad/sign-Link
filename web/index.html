Project

Sign language translation demo for the browser.

This project brings three modules into one place: text to sign playback, sign to text prediction from a webcam, and browser-based text to speech.

It uses local sign clips when they are available and falls back to generated letter cards when a matching clip is missing, so the demo can still run without the full dataset.

Notes

What this build focuses on

Current scope
  • Keep the full demo in one browser page so each module is easy to test.
  • Show how MediaPipe landmarks can be used for simple live sign prediction.
  • Play local sign clips when they exist and fall back gracefully when they do not.
  • Present the project honestly, with the current limits visible instead of hidden.

If the local model or clip dataset is missing, the page still loads and shows which parts are available.

Modules

Included in the demo

  • Text to sign playback with local clips and letter fallback.
  • Live sign to text prediction from webcam frames.
  • Detected text editing tools for spaces, backspace, and clear.
  • Browser speech output using the voices already installed on the system.
Pipeline

How the app works

  • The webcam feed is sampled in the browser and sent to the local Python server.
  • MediaPipe extracts 21 hand landmarks from the captured frame.
  • A lightweight classifier predicts the current sign label when a model file is present.
  • Generated text can be spoken in the browser or sent to the text to sign player.
Limits

Current constraints

  • Live prediction works best with one hand, steady framing, and good lighting.
  • Text to sign quality depends on which local sign clips are available.
  • When no clip dataset is installed, the translator uses generated letter cards only.
  • Speech output depends on browser support and installed system voices.
